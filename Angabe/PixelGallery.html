Aufgabenstellung

In einem Pixel-Art-Kurs zeichnen Schüler:innen kleine Bilder aus farbigen Pixeln. Die Bilder werden als Textdateien abgegeben und sollen in einer Pixel Gallery gesammelt, verwaltet und angezeigt werden.

Die Vorlage (Template/PixelGallery) enthält bereits den Großteil der Anwendung. Alle zu implementierenden Stellen sind mit // TODO (Task n) markiert (Visual Studio: View → Task List).

Vorgegeben
  • Base, Base.WpfMvvm, Base.Web: Basisklassen (GenericRepository, UnitOfWork, Transaction, RelayCommand, ...)
  • ImportConsoleApp: legt die Datenbank PixelGallery neu an (EnsureCreated, keine Migrations notwendig) und importiert Farbpalette und Bilder. Connection-String in appsettings.json (SQL Server, localhost).
  • Alle Fenster (XAML) bis auf die Farblegende, alle ViewModels bis auf die markierten Stellen, das Import-Fenster komplett.
  • Core.Tests: Unit-Tests für den Parser (ein Test fehlt).

Task 1 - Datenmodell

Für das System wurde folgendes Datenmodell erstellt:

Alle Entities erben von EntityObject (Id, RowVersion). Tabellennamen = Klassennamen. ? = nullable, UQ = Unique-Index.

  • Artist - Ersteller:in eines Bildes (Code = Verzeichnisname beim Import).
  • Picture - ein Bild. Width/Height in Pixel. Ein Bild kann (noch) keinen Artist haben.
  • Stroke - ein waagrechter "Strich" gleichfarbiger Pixel ab (Row, Column) mit der Länge Length. Durchsichtige Pixel werden nicht gespeichert.
  • PaletteColor - die Farbpalette (wird aus palette.csv importiert), z.B. R, Rot, #E53935.
  • Tag - Schlagwort, ein Bild kann mehrere Tags haben und umgekehrt.
Zu implementieren
  • Entity Tag (inkl. Navigation-Property zu Picture) - Picture.Tags existiert bereits.
  • StrokeMapping: Unique-Index (PictureId, Row, Column), Beziehungen zu Picture (Cascade Delete) und PaletteColor (Restrict).
  • TagMapping: Tabelle, Pflichtfeld + Länge, Unique-Index, m:n-Beziehung zu Picture mit der Zwischentabelle PictureTag.
Die Mappings von Artist, Picture und PaletteColor dienen als Beispiel.

Task 2 - Import

Verzeichnisstruktur (vorgegeben)

Jedes Bild ist eine Textdatei im Verzeichnis ImportData/<Artist>/, z.B. Anna\Heart_20251103.txt. Der Dateiname (ohne Endung) ist der Name des Bildes, der relative Pfad die Description, das Datum am Ende (yyyyMMdd) das Erstellungsdatum (sonst: heute). ImportFolderAsync ist bereits fertig und überspringt fehlerhafte Dateien (z.B. Ben\Broken_20251111.txt mit unbekannter Farbe X).

Dateiinhalt

# Pixel Gallery - Heart_20251103
#tags: love, red
2.3K3.3K2.
.K3RK.K3RK.
K2RW2RK5RK
KR2W8RK
K11RK
.K9RK.
2.K7RK2.
3.K5RK3.
4.K3RK4.
5.KRK5.
6.K6.
  • Zeilen, die mit # beginnen, sind Kommentare. Ausnahme: #tags: - danach folgen die Tags, durch Beistrich getrennt (Leerzeichen entfernen).
  • Leere Zeilen werden ignoriert. Jede andere Zeile ist eine Pixelzeile (Row beginnt bei 0).
  • Ein Großbuchstabe ist ein Pixel in der Palettenfarbe mit diesem Code => ein Run.
  • . ist ein durchsichtiges Pixel: kein Run, aber die Spalte wird weitergezählt.
  • Wiederhol-Prefix: eine (auch mehrstellige) Zahl vor einem Zeichen wiederholt es: 3R = RRR => ein Run mit Length = 3, 12L => Länge 12. Der Prefix wird nach jedem Kommando zurückgesetzt.
  • Alle anderen Zeichen (z.B. Leerzeichen) werden ignoriert.
  • Width = längste Zeile, Height = Anzahl der Pixelzeilen.
Zu implementieren
  • PixelParser.Parse (Core) - liefert ParseResult(Tags, Runs, Width, Height).
  • ImportService.ImportPictureAsync (Persistence):
    • Pro Bild ist eine Transaktion vorzusehen. Bildnamen sind eindeutig.
    • Unbekannter Farbcode => InvalidOperationException (das Bild wird nicht importiert).
    • Artist und Tags werden wiederverwendet oder neu angelegt.
    • Es müssen die Navigation-Properties verwendet werden - nur ein AddAsync für das Bild.

Unit-Tests

Im Projekt Core.Tests sind sieben Tests für den Parser vorgegeben - sie müssen nach Ihrer Implementierung grün sein (dotnet test).

Zu implementieren Schreiben Sie den Test Parse_PrefixIsResetAfterCommand (derzeit Assert.Inconclusive): Für die Zeile 3R.B wird ein Run R (Spalte 0, Länge 3) und ein Run B (Spalte 4, Länge 1) erwartet, die Breite ist 5.

Task 3 - WPF

Die Verwaltung der Bilder erfolgt mit einer WPF-Anwendung (MVVM).

Hauptfenster

  • Artists (links): <All> und alle Artists der DB. Die Auswahl filtert die Liste sofort.
  • Tag (oben): mit Search werden nur Bilder angezeigt, die einen Tag haben, der den Text enthält. Beide Filter wirken gemeinsam.
  • Die Liste ist nach CreatedOn absteigend (dann Name) sortiert. Pixels ist die Summe der Stroke-Längen, Tags sind alphabetisch und durch Beistrich getrennt.
  • Selected picture (rechts): Mini-Vorschau des ausgewählten Bildes (gleiches Control wie im Preview-Fenster).
  • Die Statusleiste zeigt Anzahl der Bilder und Summe der Pixel.

Artist ändern

  • Edit startet den Bearbeitungsmodus: nur dann ist die Artist-ComboBox aktiv, Liste, Filter und Import sind gesperrt.
  • Save speichert den neuen Artist - (none) setzt den Artist auf null. Cancel verwirft die Änderung.
  • Open preview und Edit sind nur aktiv, wenn ein Bild ausgewählt ist (und nicht bearbeitet wird), Save/Cancel nur im Bearbeitungsmodus.
Zu implementieren
  • PictureRepository.GetOverviewAsync(artistId, tag): Filtern, Sortieren und Projektion auf PictureOverview erledigt die Datenbank - das Laden der gesamten DB in den Hauptspeicher ist nicht zulässig.
  • MainWindowViewModel: die CanExecute-Bedingungen der vier Commands und SaveAsync.

Bildvorschau

  • Das Bild wird mit einem Custom Draw (PicturePreviewControl.OnRender) gezeichnet: jeder Stroke als gefülltes Rechteck in seiner Palettenfarbe. Das Bild wird gleichmäßig skaliert (Seitenverhältnis bleibt) und zentriert.
  • Mit Show grid wird zusätzlich ein Gitter über alle Pixel gezeichnet.
  • Colors: Farblegende als ItemsControl mit DataTemplate (Farbfeld, Name, Anzahl Pixel), absteigend nach Anzahl der Pixel sortiert.
Zu implementieren
  • PicturePreviewControl.OnRender (Dependency-Properties sind vorhanden).
  • PicturePreviewViewModel: ColorUsages befüllen.
  • PicturePreviewWindow.xaml: ItemsControl mit ItemTemplate/DataTemplate für ColorUsages.

Bild importieren (vorgegeben)

Der Dialog ist fertig: Import ist nur aktiv, wenn die Datei existiert; das Erstellungsdatum ist heute. Die Vorschau rechts verwendet bereits Ihren Parser und Ihr Custom-Draw-Control.

Task 4 - WebAPI

Das Projekt WebApi ist vorbereitet (DI, Swagger, ArtistsController als Beispiel). Im PicturesController sind die DTOs bereits vorhanden.

Zu implementieren: GET /Pictures/{id}
  • 200 OK mit PictureDetailDto: Basisdaten, Name des Artists (oder null), Tags (alphabetisch) und je verwendeter Farbe die Anzahl der Pixel (Colors, absteigend nach Pixels).
